# CLAUDE.md — Frontend Website Rules (Mobile App prototype)

## Always Do First
- If a `frontend-design` skill is available in the session, invoke it before writing frontend code. Otherwise apply the Anti-Generic Guardrails below.

## Reference Images
- If a reference image is provided: match layout, spacing, typography, and color exactly. Swap in placeholder content (images via `https://placehold.co/`, generic copy). Do not improve or add to the design.
- If no reference image: design from scratch with high craft (see guardrails below).
- Screenshot your output, compare against reference, fix mismatches, re-screenshot. Do at least 2 comparison rounds. Stop only when no visible differences remain or user says so.

## Local Server
- **Always serve on localhost** — never screenshot a `file:///` URL.
- Start the dev server: `node serve.mjs 3001` (serves the project root at `http://localhost:3001`)
- Port 3000 is NOT ours — another app (an "Agile Pharmas" dev server) already listens there. This project uses **3001**.
- `serve.mjs` lives in the project root; it takes the port as its first argument (default 3000). Start it in the background before taking any screenshots.
- If the server is already running, do not start a second instance.

## Screenshot Workflow
- Puppeteer is installed locally in this project (`node_modules/`). Its Chrome browser cache lives at `C:\src\puppeteer-cache` (set via `.puppeteerrc.cjs`) — an ASCII-only path, because the user profile folder contains Arabic characters that can break Chrome tooling.
- **Always screenshot from localhost:** `node screenshot.mjs http://localhost:3001`
- Screenshots are saved automatically to `./temporary screenshots/screenshot-N.png` (auto-incremented, never overwritten).
- Optional label suffix: `node screenshot.mjs http://localhost:3000 label` → saves as `screenshot-N-label.png`
- `screenshot.mjs` lives in the project root. Use it as-is.
- After screenshotting, read the PNG from `temporary screenshots/` with the Read tool to see and analyze the image directly.
- When comparing, be specific: "heading is 32px but reference shows ~24px", "card gap is 16px but should be 24px"
- Check: spacing/padding, font size/weight/line-height, colors (exact hex), alignment, border-radius, shadows, image sizing

## Output Defaults
- Single `index.html` file, all styles inline, unless user says otherwise
- Tailwind CSS via CDN is the default for NEW pages: `<script src="https://cdn.tailwindcss.com"></script>`
- **Exception — the current `index.html`:** it uses hand-written inline CSS (no Tailwind) because it is also published as a claude.ai artifact, whose CSP blocks all CDN scripts. Keep it CDN-free unless the artifact is abandoned.
- Placeholder images: `https://placehold.co/WIDTHxHEIGHT`
- Mobile-first responsive

## Brand Assets
- Always check the `Assets/` folder before designing (this project's asset folder; the generic rule says `brand_assets/`). It may contain logos, color guides, style guides, or images.
- The quick-action icons in `Assets/` are glossy orbs on black backgrounds — run `node process-icons.mjs` to circle-crop and inline them into `index.html` (outputs also saved to `Assets/processed/`).
- If assets exist there, use them. Do not use placeholders where real assets are available.
- If a logo is present, use it. If a color palette is defined, use those exact values — do not invent brand colors.

## Anti-Generic Guardrails
- **Colors:** Never use default Tailwind palette (indigo-500, blue-600, etc.). Pick a custom brand color and derive from it.
- **Shadows:** Never use flat `shadow-md`. Use layered, color-tinted shadows with low opacity.
- **Typography:** Never use the same font for headings and body. Pair a display/serif with a clean sans. Apply tight tracking (`-0.03em`) on large headings, generous line-height (`1.7`) on body.
- **Gradients:** Layer multiple radial gradients. Add grain/texture via SVG noise filter for depth.
- **Animations:** Only animate `transform` and `opacity`. Never `transition-all`. Use spring-style easing.
- **Interactive states:** Every clickable element needs hover, focus-visible, and active states. No exceptions.
- **Images:** Add a gradient overlay (`bg-gradient-to-t from-black/60`) and a color treatment layer with `mix-blend-multiply`.
- **Spacing:** Use intentional, consistent spacing tokens — not random Tailwind steps.
- **Depth:** Surfaces should have a layering system (base → elevated → floating), not all sit at the same z-plane.

## Hard Rules
- Do not add sections, features, or content not in the reference
- Do not "improve" a reference design — match it
- Do not stop after one screenshot pass
- Do not use `transition-all`
- Do not use default Tailwind blue/indigo as primary color

## MedsCheck Pre-flight
- The MedsCheck session opens with 5 guided micro-steps (Modality → Provider → Reason → Caregiver → Lifestyle) inside the Pre-flight top-level tab; state lives in the in-memory `PRE` object keyed by patient id, so back navigation and interruptions never lose entered data.
- Reason step enforces the real minimum of 3 reasons (auto-detected from record data: 3+ meds, 2+ conditions, 2+ prescribers) with inline amber messaging and a disabled Next.
- Modality ("Phone") is stored in `PRE[pid].modality` and drives the Acknowledgement tab (built): In-person → patient signs; Phone → "Conducted by phone with [name] on [date]" + pharmacist signs. Signature stored as data URL in `PRE[pid].ack`; empty signature disables Confirm (error prevention).
- The canvas signature pad is THE reusable signature component: `attachSigPad(canvas, hint, initialDataUrl, onChange)` returns `{inked, dataUrl, clear, load}`. Reuse it for the Worksheet's Personal Medication Record instead of building a new one.
- Acknowledgement has "Sign in full screen" (`openSigFullscreen`): a landscape overlay (`.sig-full` > `.sig-rot`, rotated 90°) where the whole phone is the pad; `attachSigPad` detects `.sig-rot` and remaps pointer coords. Done → the signature flows back into the inline pad (aspect-fit) and enables Confirm.
- Notify tab (built): "No action" (default, neutral filing line) / "Follow-up action" (textarea + violet "Draft with AI" chip composing from `PRE[pid].worksheet.flags` when the Worksheet exists, else pre-flight reasons; blue info banner names the Pre-flight provider; fax is simulated). Complete requires a non-empty note when follow-up is chosen.
- "Complete MedsCheck →" pushes a claim {service, $60, patient, status: "ready"} onto the in-app `BILLING` array and navigates to the Billing screen (`renderBilling`) — this project's equivalent of the other app's `billing.html`. The home Billing tile opens the same screen.
- Informational blue (#e8f1fd/#2f6fd0) and AI violet (#f1edfc/#7c5cd6) are now instantiated per behavioral_ux_design_director.md §11 — use only for info banners / AI-drafted content respectively.

## Scan-first list pattern (2026-08-24 — density/scanability spec; REUSABLE GLOBALLY)
- **The rule**: a list answers only what/when/status/needs-action; everything else lives in a detail view. "Show enough to recognize and prioritize — not enough to fully understand."
- **Event Log rows** (`.inc-row`, whole row `role=button` → chevron): quiet date column · title (`-webkit-line-clamp: 2` — max 2 lines per rule 11) · ONE ellipsized metadata line with **short stage labels** (`INC_STAGE_SHORT`: "Preparation / dispensing"→"Dispensing", "Rx order entry"→"Order entry"…) + first med only ("Hydralazine +1") · `.pl-line` with ONE dominant status pill (+ `NIDR pending` ONLY when sync is actionable). Kind/harm/NIDR-submitted/descriptions moved OUT of rows. ≥4 rows fit the first viewport.
- **Event details** (`#scrIncDetail`, `renderIncDetail(i)`, row tap): the information destination — full pills row (status/kind/NIDR), **one clear action** for open items ("Mark analysis complete →" / "Mark learnings shared →" → status Complete + green flash + bell resync), kv card (Category / harm / full stages / all meds+DIN / Discovered by / de-identified patient context / NIDR hint), What happened, Contributing factors, Immediate actions. Recorded events now store desc/factors/actions/disc/context for this screen; seeds carry short de-identified descriptions.
- **Incremental loading**: `incShown = 10` + "Load more · N older" `.btn-outline` that only renders when `INCIDENTS.length > incShown` (rule 8: never for small datasets). Filters intentionally NOT added (dataset small — rule 9).
- **Apply to any long list** (activity, billing, histories, claims…): summarize in the list → detail on tap → load incrementally when long. Audited existing lists: Patients / Billing / Notifications / Calendar rows already conform (≤1 pill, 2-line rows).
